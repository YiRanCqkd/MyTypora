# Typora 对比问题修复记录

本轮修改集中在 `UniReadMD-WebUI` 的 Electron 与 Vue 编辑器，修复前次工程分析中发现的
安全、丢稿、原地编辑、资源加载、导出与工作区问题。原有 MFC 工程及旧 Typora 资源没有修改。
用户原有的依赖、打包脚本与其他未提交内容保留；本轮尚不具备完整发布资格。
仓库中跟踪的前端构建产物已同步更新，现有安装包与独立 EXE 尚未重新生成。

## 已实现的修改

| 范围 | 修复后的行为 |
| --- | --- |
| Markdown 安全 | 原始 HTML、公式和图表输出净化，清除事件属性、危险协议及伪造编辑映射 |
| Electron 安全 | 开启沙箱和网页安全，校验 IPC 主框架与窗口，限制导航及文件授权 |
| 本地图片 | 按文档目录解析中文、空格和 Windows 路径，通过窗口能力读取受限图片 |
| 文档切换 | 打开、新建、关闭、最近文件和外部接管共用未保存保护；保存失败中止切换 |
| 文档撤销 | 切换文档重建 CodeMirror 状态，撤销不会把上一文档内容带入当前文件 |
| 写入完整性 | 同目录临时文件、同步与原子替换；串行写入，检测外部修改、移动或删除 |
| 草稿恢复 | 主进程按窗口保存草稿，跨随机端口恢复；损坏快照不影响其他草稿 |
| 自动保存 | 默认关闭，可在偏好设置开启；约每两秒检查已命名的脏文档并保存 |
| 原地编辑 | 单击块进入编辑，实时回写 Markdown，Esc 回滚，提交可撤销 |
| 公式与图表 | 首次公式加载刷新预览；Mermaid 使用 strict，图表 SVG 再次净化 |
| 工作区 | 新建文档、打开文件夹、递归树、折叠、树与列表、排序及文件夹正文搜索 |
| 设置 | 系统主题随配色变化，保留源码模式；用户 CSS 净化后限定在预览区域 |
| 导出 | 复用实际预览、样式、字体和图表；本地图片内嵌，长文图片捕获全文 |
| 可选导出 | 补齐 DOCX、ODT、RTF 菜单，检查 Pandoc 3.10，缺能力时禁用 |
| 质量 | 升级安全依赖，补充回归测试，清空 E2E 失败豁免，统计全部 JavaScript 包体 |

HTML 导出移除脚本及危险嵌入对象，并携带独立 CSP。PDF、PNG 和 JPEG 使用同一份导出
文档，等待字体、图片和图表准备完成。Pandoc 使用源文档目录作为资源路径，关闭原始
HTML/TeX 输入，导出前拒绝越界本地图片。导出目标扩展名必须与格式一致。

导出的内嵌字体可能超过 1 MiB，因此导出样式遵循 20 MiB 输入边界；用户选择的 CSS
仍限制为 1 MiB。用户 CSS 的根相邻选择器和带转义的资源声明会被移除。

## 边界与兼容性

- 文档与导出源各限制为 20 MiB；恢复快照为 25 MiB，容纳文档与 JSON 状态字段。
- 工作区扫描最多 12 层、2000 个目录和 10000 个文档，跳过符号链接、目录联接、
  `.git` 和 `node_modules`；约五秒刷新一次。
- 正文搜索最多扫描 64 MiB、十秒和返回 200 条匹配；点击结果打开对应文档。
- 图片限制为 20 MiB；全文图片超过 32767 像素高或 6400 万像素时提示使用 PDF。
- 自动保存只作用于已经命名的文档；新草稿由会话快照保护。
- 旧 IPC 名称与主要返回字段保留，新接口和资源版本字段以扩展方式加入。

## 验证结果

| 检查 | 本轮结果 |
| --- | --- |
| 前端单元测试 | 86/86 通过 |
| 核心模块覆盖率 | 语句 96.62%、分支 91.15%、函数 98.74%、行 96.50% |
| 安全净化与文档守卫 | 两者行覆盖率 100%，分支分别为 96.07% 与 93.10% |
| 全量前端覆盖率基线 | 85 项通过，行 36.93%、分支 25.55%，尚未达到 90% |
| Electron 合同及回归 | 22/22 通过，包含实际临时文件写入、授权、联接环和损坏快照 |
| 质量脚本测试 | 20/20 通过 |
| 浏览器 E2E | 完整回归 41/41 通过，包含五个视觉基线，无跳过、无失败豁免 |
| 类型检查与 Lint | 通过 |
| 根工程与前端依赖审计 | 两者均为零漏洞 |
| 构建包体 | 主包 181.29 KiB，全部 JavaScript 4359.04 KiB，预算检查通过 |

覆盖率门槛统计 `src/services`、`src/utils`、安全净化与文档守卫；后两个新增核心文件
各自必须达到 90%。核心模块达标不表示所有 Vue 组件与功能模块达到 90%；关键交互另由
浏览器 E2E 覆盖。全量基线不包含独立依赖兼容测试，所以比前端总测试少一项。
Pandoc 转换及 Chromium 全文尺寸的 Node 测试使用模拟引擎，不能替代真实导出验收。

中间一轮 E2E 为 39/41：主题控件定位错误以及页面创建超过 30 秒。修正为按可访问角色
定位，并将测试总时限设为 60 秒后，完整重跑 41 项通过；业务断言仍维持十秒。
视觉基线经过查看更新，反映偏好入口、当前正文宽度与恢复后的编辑浮层。

最后增加图表颜色断言后，发现 Mermaid 的动画规则曾导致整份样式被净化移除。改用
PostCSS 移除危险规则、保留限定在当前 SVG 的静态样式，并将图表与首次公式回归单独
重跑，两项均通过，图表填充色也通过断言。最终改动后没有再重复整套 41 项回归。

## 未完成的验证及后续差距

真实 Electron 44.7.0 可执行文件已下载，但本机启动返回 `Access is denied`，进程在原生
断言执行前退出。已加入隔离用户数据目录的 `test:native`，覆盖沙箱、打开、中文图片、
公式、冲突保护、撤销、全文 PNG 及跨端口恢复，需在允许启动 Electron 的环境复验。

PDF/图片真实产物、真实 Pandoc 3.10 转换、unpacked 应用和安装包冒烟尚未通过本轮验证。
现有性能脚本统计字符串解析与模拟滚动，不能证明实际 Electron 启动、绘制或大文档编辑
性能。CI 配置已补入审计、包体与原生检查，但未实际执行远端 CI；原有固定本机工具链
测试仍需在 CI 环境完成适配。

现有性能检查在停止其他测试后仍失败：5 MiB 解析为 1121.80 ms，对照旧基线 835.32 ms；
字符串搜索为 111.18 ms，对照旧基线 85.01 ms。本轮保留性能门槛与失败报告，没有修改
基线、放宽阈值或设置 `PERF_APPROVE`；真实性能与这两项退化仍需要后续处理。

文件重命名、删除、新建子目录、剪贴板图片落盘，以及更细致的恢复提示和外部变更交互
仍属于相对完整 Typora 的后续差距。F1-F4、FA 和完整发布审核保持未完成，不归档变更，
不生成 `release-ready.json`。

本轮证据保存在仓库根 `.omo/evidence/typora-parity-fixes/`，仅包含约定的七个文件。
历史失败记录明确标记为历史观察，不冒充本轮重现或初始源文件哈希。
