# 设计

## 授权与兼容
用户“按建议优化”已授权本次建议范围，按任务顺序实施，不重复请求确认。
CodeMirror 保持 Markdown 唯一数据源；现有块编辑和已保存设置兼容。
文件系统写入继续由主进程执行，资源路径必须通过原有授权和真实路径检查。

## 方案
1. 使用 Markdown 语法树确定最小行内编辑范围，DOM 只隐藏当前片段。
   结构不适用时回退到块编辑；输入法、撤销和文档切换沿用现有会话。
2. 选区统计跟随实际焦点，使用同一字数规则，避免跨文档残留。
3. 公式以文档为范围收集标签和编号，引用先收集后渲染；化学扩展使用现有 KaTeX。
4. 图片整理复制本地已授权资源并改写实际 Markdown 引用，保留代码示例和原图。
5. 新导出能力使用固定格式、受限选项，失败保持原输出文件。
6. 写作主题采用受控 CSS 变量，明暗各自持久化，不破坏用户自定义 CSS。
7. 大文档快速路径仅覆盖确定等价的纯文本段落和普通标题，其他语法走完整解析器。
   图表渲染有任务队列、缓存和卸载清理，导出显式请求完整渲染。

## 验证
新增行为先保存失败证据，再执行单元、类型、代码检查和浏览器验证。
发布时生成独立 NSIS，并验证包内代码、实际转换及原生主要流程。
覆盖率和性能原门禁独立记录，用户部署与人工交互未完成前保持未归档。
