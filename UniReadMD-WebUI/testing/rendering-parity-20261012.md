# 渲染展示差异与正文编辑问题回归（2026-10-12）

## 结论

用户反馈的左侧“第二个光标”来自活动段落的装饰阴影；单击正文立即变高，
来自旧安装版对活动段落使用 `white-space: pre-wrap`，让渲染器输出的
`<br>` 与相邻文本换行重复占位。它们是可视编辑状态样式问题。

正式安装中的旧 1.1.0 未包含上一轮源码的行距修复。本轮删除装饰阴影，
将已有行距修复重新构建进独立的 1.1.0 安装包，并新增普通正文回归。
没有通过删除正常段落边距来掩盖问题，也没有改写用户文档。

## 对比范围与方法

- 本机 Typora 版本为 1.2.4；默认样式的数值对照以其内置 GitHub 主题为准。
  Typora 其他主题可能不同，不能将这些数值当作所有版本和主题的固定标准。
- UniReadMD 使用当前源码、生产构建和独立配置的原生应用进行验证。
- 样本为同目录的 `rendering-parity-cases.md`，包含正文、列表、表格、代码、公式和图表。
- Typora 样式文件只读。样式参考模型复用同一份 HTML，不能代表 Typora 的完整编辑器、
  Markdown 解析器或真实应用验收。空格、换行等行为另参考官方文档。

## 仍存在的渲染与编辑差异

| 优先级 | 项目 | Typora 对照 | UniReadMD 当前状态与影响 |
| --- | --- | --- | --- |
| 高 | 连续空格及换行策略 | 可分别配置编辑展示与导出处理 | 正文连续空格合并；单换行固定渲染为换行，缺少独立导出偏好 |
| 高 | 复杂块编辑连续性 | 在文档流中提供表格、公式等专用编辑交互 | 简单正文已原位编辑；含子列表的列表项、含图片或公式的段落仍使用块编辑框 |
| 中 | 正文宽度 | 本机 GitHub 主题居中并限制最大宽度 | 当前随可用区域铺满，大屏一行文字更长 |
| 中 | 默认字体及行高 | 本机 GitHub 主题优先 Open Sans，行高 1.6 | 优先 Segoe UI，行高 1.75；中英混排、折行和密度不同 |
| 中 | 表格尺寸与折行 | 本机 GitHub 主题单元格横向内边距 13px | 横向内边距 10px，表格铺满；列宽及长内容折行可能不同 |
| 中 | 代码高亮语言范围 | 官方支持列表包含 PowerShell、C# 等 | 当前注册 14 种语法；PowerShell、C# 仅显示普通代码文本 |
| 中 | 数学排版兼容性 | 使用 MathJax，可选 physics 等扩展 | 使用 KaTeX；常用公式、化学式、宏和编号已支持，部分命令及间距不同 |

### 正文宽度的具体区别

本机 Typora GitHub 主题的 `#write` 默认最大宽度 860px，窗口视口达到
1400px 时为 1024px，达到 1800px 时为 1200px，居中显示并保留内部留白。
这是主题规则。官方允许通过主题调整书写区域宽度。

UniReadMD 的 `--content-max-width` 为 `100%`，两侧默认各 48px，较窄视口改为 24px。
窗口放大时充分展开符合用户此前诉求，但长段落的阅读行长与 Typora GitHub 主题不同。
后续适合提供“居中阅读宽度”和“铺满窗口”的选择，并保留当前宽屏展开能力。

参考：[Typora 书写区域宽度](https://support.typora.io/Width-of-Writing-Area/)、
[自定义主题](https://theme.typora.io/doc/Write-Custom-Theme/)。

在 1304×815 的同一视口、相同可用区域和 100% 内容缩放下，取得以下诊断数据。
Typora 列仅表示本机主题的样式参考模型，并非完整 Typora 应用截图或验收结果。

| 指标 | UniReadMD 原生应用 | Typora GitHub 样式模型 |
| --- | --- | --- |
| 内容外框宽度 | 1004px | 860px |
| 普通段落实际宽度 | 900px | 800px |
| 正文字号 / 行高 | 16px / 28px | 16px / 25.6px |
| 一级标题字号 / 行高 | 36px / 43.2px | 36px / 43.2px |

诊断文件：`../release/rendering-20261012/rendering-audit.json`。
样本中的 JavaScript 产生语法高亮节点，PowerShell 和 C# 没有高亮节点，
与当前注册的语言范围一致。样式模型复用渲染 HTML，不能用来判断 Typora 的空格解析
或语法高亮能力；这两项差异分别由官方文档与产品源码确认。

### 空格与换行需要独立处理

UniReadMD 的 Markdown 渲染器固定启用 `breaks: true`。普通正文使用浏览器正常空白
处理，连续空格会合并。Typora 官方文档区分编辑时保留空格、换行与打印导出时的处理，
并提供相应偏好设置。后续应明确编辑、HTML 导出和打印三者的策略。

不能简单将全部正文切换为 `pre-wrap`：渲染 HTML 中已有 `<br>` 时，原始文本换行
会再次占位，正是本次旧安装版高度增加的原因。

参考：[Typora 空格与换行](https://support.typora.io/Line-Break/)。

### 现有能力与对比边界

- 标题、粗体、斜体、删除线、链接、引用、任务列表、表格三种对齐、脚注已经支持。
  标题尺寸和普通段落边距多项已接近 GitHub 主题，不应重复报告为功能缺失。
- 已有用户 CSS 加载能力；差异主要是默认主题、可用的界面设置以及主题兼容程度。
- Mermaid 中文节点与离线导出已有专项回归。没有同样输入的实测证据时，
  不将不同引擎版本可能造成的布局差别报告为确定缺陷。
- 数学插件名虽保留 `markdown-it-mathjax3`，Vite 实际映射到本地 KaTeX 实现。
- 表格已有单元格编辑和行列操作，与 Typora 的完整表格交互仍有差别，
  但不能将对齐或基本表格显示列为缺失。
- HTML 过滤与 CSP 限制主动内容。后续对齐展示能力时应保留安全过滤。

参考：[Typora 代码语言支持](https://support.typora.io/Code-Fences-Language-Support/)、
[数学公式](https://support.typora.io/Math/)、
[表格编辑](https://support.typora.io/Table-Editing/)。
