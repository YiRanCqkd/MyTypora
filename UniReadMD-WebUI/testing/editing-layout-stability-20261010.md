# 正文编辑与模式切换布局修复

日期：2026-10-10。版本保持 1.1.0。

## 问题与修复

- 原位编辑块使用 `white-space: pre-wrap`，将 Markdown 渲染器输出的 `<br>` 后的
  HTML 排版换行再次显示。三行正文的复现用例进入编辑后高度增加 56 CSS 像素。
  活动块现沿用原正文的换行、折行和行高规则。
- 活动块原有 `min-height: 1.6em` 覆盖标题的紧凑高度。一级标题复现增加
  13.40625 CSS 像素。删除活动块专属最小高度；空文档仍沿用已有空行样式。
- DOM 转 Markdown 时，`<br>` 与其后的排版换行被重复转换，编辑提交后可能拆开段落。
  现仅跳过紧随换行标签的一个排版换行，保留其他文本空格和连续换行标签。
- 顶部栏与底部状态栏的侧栏偏移原来排除了源码模式，切换模式会横移 300 CSS 像素。
  现两栏仅由侧栏显示状态和响应式布局决定位置；源码开关不再改变它们的偏移。
  同时恢复窄窗口媒体规则的正常优先级。

这些属于恢复已有原位编辑和独立侧栏行为的缺陷修复，依据项目 OpenSpec 的缺陷修复豁免
直接实施；没有新增功能或改变内容宽度策略。

## 内容展示区宽度对比

只读核对本机 Typora 1.2.4 的内置 GitHub 主题：
`D:/Program Files/Typora/resources/style/themes/github.css` 第 52 至 68 行。
不同主题与用户自定义 CSS 可以使用其他宽度，不应将下面的值视为所有 Typora 的统一默认值。

| 窗口视口宽度（CSS 像素） | GitHub 主题内容容器最大宽度 |
| --- | --- |
| 小于 1400 | 860 |
| 1400 至 1799 | 1024 |
| 至少 1800 | 1200 |

Typora 规则为 `max-width`、`margin: 0 auto`、左右各 30 像素内边距。
基础样式采用 `border-box`，上述最大宽度包含内边距。
媒体断点依据窗口视口；侧栏占用后剩余空间不足时，正文容器随可用空间缩小。
因此大窗口下正文居中，两侧留白增加，单行长度受到控制。

UniReadMD 当前采用 `width: 100%` 和 `--content-max-width: 100%`，普通与专注模式
均随可用工作区展开。左右内边距为 48 像素，窗口宽度不超过 1080 时为 24 像素。
源码视图也沿用可用宽度，内容缩放主要改变正文字号，没有引入阅读列宽上限。

例如窗口视口为 2000、侧栏为 300、内容缩放为 100% 时，忽略滚动条和边框：
Typora GitHub 正文约为 `1200 - 60 = 1140` 像素；
UniReadMD 正文约为 `2000 - 300 - 96 = 1604` 像素。

本次保留用户此前确认的“窗口放大后内容充分展开”规则。若后续需要进一步贴近 Typora，
可单独增加居中阅读宽度与铺满窗口两种选择，且让预览与编辑共享同一宽度规则。

官方说明：
[调整写作区域宽度](https://support.typora.io/Width-of-Writing-Area/)、
[编写主题](https://theme.typora.io/doc/Write-Custom-Theme/)。
